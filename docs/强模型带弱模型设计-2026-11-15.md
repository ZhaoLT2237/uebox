# 强模型带弱模型设计（2026-11-15）

**状态**：设计稿第二版，代码还没动。第一版以“参数化脚本”为核心，用户认为那是专用知识，不是通用知识，已经推翻。下面提到的代码事实，都已对照 `main` 核过。

---

## 0. 结论先行

强模型（比如 Fable 5.2）做完一个 UE 任务后，在**同一个会话里**接着复盘，留下两样东西：

- 一页**思路**：拆解的顺序、怎么验证、怎么排错；
- 若干条**手册条目**：每条都挂在具体的类、节点或工具上。

盒子先核对证据，再到引擎里验一遍，然后写进经验库。之后弱模型（比如 DeepSeek）做同一领域的**其他**任务时，只要碰到这些类、节点或工具，盒子就把对应的条目递给它，不需要它自己去查。

打个比方：老师傅收工前在车间里走一圈，在每台机器上挂一张卡片，写着“新手用这台最容易错在哪、正确做法是什么”。徒弟一碰这台机器，卡片就到了眼前。

**为什么不用知识库加向量检索**：旧长期记忆下线有四个原因，换成知识库照样会碰上：垃圾多、召回不准、依赖嵌入模型、说不清有没有用。另外，弱模型不知道自己哪里不会，靠它自己去拉取就失效了。而且平常干活的会话里根本没有检索工具：没有绑定知识库，就不会注册 `search_notebook_sources`。

## 1. 硬约束：“执行前递过去”做不到免费

pi 的 `BeforeToolCallResult` 只有 `block`、`reason`、`terminate` 三个字段。也就是说，调用前只能拦下这次调用，不能给一个放行的调用附上话。所以递条目只有三个时机：

| 时机 | 怎么做 | 用在哪 |
|---|---|---|
| 跟这次调用一起 | 挂在这次调用的结果后面（`afterToolCall`） | **主路径** |
| 更早的动作 | 写计划（`update_plan`）、加载工具（`search_tools`）时附上 | 真正的事前 |
| 拦一次 | 现有的 `precheck`，会多一个来回 | 只用于确定的错误写法 |

## 2. 复盘

| 项 | 设计 |
|---|---|
| 何时 | 任务验收后，跟着技能页现有的“自动记录做法”开关走，不另加按钮：设为“先确认”时，模型在收尾时问一句要不要复盘、留下手册；设为“自动”时直接复盘；设为“关闭”时不复盘。复盘在原会话里多跑一轮，这时编辑器还开着，探针一定能用 |
| 谁来做 | 会话自己的模型。现在的整理员用的是默认模型（`scheduler.ts` 的 `defaultComplete` → `resolveBinding({})`），不能复用。离线补跑时，要在 `TrailHeader` 里加 `model` 字段 |
| 输入 | 老师自己的上下文；盒子从原始账算出的挂钩清单（本次**成功**调用里出现过的类、成员、节点、组件类和工具，带调用序号）；最终的资产列表 |
| 规则 | 只写通用的，要过 `mentionsProjectOwned`。按“新手做这一步会错在哪”来想，但**正文只写正确做法**，新手的错法只当作挂钩。每条都要引用证据（某次成功调用的序号）。事实类条目要过探针 |
| 交付 | 用一个新工具 `experience_submit(JSON)` 交，不直接写文件，经验库仍然只有一个写者。盒子当场校验，不合格的连同原因退回，老师在同一轮里改。**这个工具只在复盘那一轮临时挂上**，平时的工具清单和 `search_tools` 都找不到它，免得学生在自己的会话里往手册里写东西 |
| 放哪层 | 复用 `decideLayer` |

**条目字段**（在 `experienceFile.ts` 里新增）：

| 字段 | 内容 |
|---|---|
| `kind` | `fact` 或 `practice` |
| `on` | 挂钩，比如 `sym:boxcomponent`、`node:ComponentBoundEvent`、`tool:ue_input_add_mapping` |
| `warns` | 新手错法的挂钩，比如 `sym:editorlevellibrary` |
| `advice` | 正确做法，不超过 300 字 |
| `uses` | 采纳判据：这张卡片教的那个具体做法，形式是“参数名=值”或者一段代码，比如 `generate_overlap_events=true`。**不能和 `on` 里的任何挂钩相同**：学生碰到挂钩、卡片才出现，所以挂钩出现了不能算“照做了”。写不出这样一个判据的卡片，`uses` 留空，不统计采纳 |
| `evidence` | 证据，引用成功调用的序号 |
| `source` | `teacher · <模型> · 日期 · 会话` |

`errorPattern` 允许为空。`patternProblem` 会把空的判成“太短”，所以这类条目不会被报错召回误配。

**以数字门跑酷为例，老师会留下的条目：**

| 正确做法 | 挂钩 |
|---|---|
| 人群用一个 ISM/HISM 组件加多个实例，批量更新变换。**适用条件：成员不需要各自的骨骼动画** | `on` ISM/HISM，`warns` `node:SpawnActor` |
| 门用 BoxComponent，两边都要开 Overlap；用一次性闩锁防止重复触发 | `sym:boxcomponent`、`sym:oncomponentbeginoverlap` |
| Enhanced Input：建好 IA 和 IMC，在 BeginPlay 里用 `EnhancedInputLocalPlayerSubsystem` 加映射 | `tool:ue_input_add_mapping`、`sym:enhancedinputlocalplayersubsystem` |
| 世界里的数字：数量多时用 TextRenderComponent，要样式时用 WidgetComponent 并设置 draw size | `sym:textrendercomponent`、`sym:widgetcomponent` |
| 用 Python 建蓝图：`AssetTools.create_asset` + `BlueprintFactory`；加组件优先用盒子的蓝图工具 | `sym:blueprintfactory`，`warns` `sym:simple_construction_script` |
| 摆放 Actor 用 `EditorActorSubsystem` | `warns` `sym:editorlevellibrary` |

## 3. 递送

**抽挂钩**（新文件 `anchors.ts`，纯字符串处理）：

- Python 代码里的 `unreal.X`、`unreal.X.y`、`get_editor_subsystem(unreal.X)`；
- 工具参数里的 `component_class`、`parent_class`、节点的 class 和 member；
- 工具名本身；
- `update_plan` 的文本。

抽出来的名字统一转成小写，然后做精确匹配。U/A 前缀和 `_C` 后缀只在蓝图和 C++ 来源的类名上去掉（例如工具参数里的 `AActor`、`BP_Gate_C`）。Python 里的名字原样保留：`unreal.AIController` 本来就没有前缀，按规则去掉 A 会变成 `IController`。

**排序和上限**：

- `warns` 命中的排最前，说明它正要犯错；然后是已验证在试用前、本工程在通用前。
- 每次调用最多 2 条，每个会话最多 10 条（约 3k token），同一条每个会话只出现一次。

**措辞**：`[UE 手册 · 与这一步用到的 X 有关]` + 正确做法 + “已经这么做了就忽略”。

**和现有机制的关系**：

- 报错时召回照旧。
- `warns` 里的写法如果经探针确认“不存在”，就生成 `avoid`，接进 `precheck` 拦一次。
- “已弃用但还能用”的写法不拦。

## 4. 思路技能

- 内置一个技能 `ue-method`，最多 60 行。固定三节：拆解顺序、每步怎么验证、排错套路。
- **不放进系统提示词。** 工具从 2026-11-08 起已经全部按需加载；经验设计稿也引用过研究，说明按需给比常驻好；系统提示词里已经有“改完要截图确认”这类通用要求，再放进去会重复，Fable 自己干活时也得白白多带 60 行。
- 递送时机：会话里第一次调用 `update_plan` 时，在结果后面附一句，提示有这个技能、用它的名字加载。和卡片走同一条递送路径。
- 要不要改成常驻，看评测第 ② 组和第 ③ 组的差距再定。
- 以后的老师复盘时，只能提交“替换”或“合并”，总数封顶 12 条：要加一条，就得删一条。同义的合并，计数加一。

## 5. 记功和退休

| 项 | 规则 |
|---|---|
| 采纳 | 递出后 5 步内，后面的代码或参数里出现了 `uses`；或者递出时命中了 `warns`，之后那个写法不再出现。`uses` 为空、也没命中 `warns` 的卡片，不统计采纳 |
| 成功 | 那次调用成功，而且窗口内没有挂在同一挂钩上的报错 |
| 退休 | 只有两种情况：探针否定；照着做了，还在同一个挂钩上报错，累计 2 次 |
| 不因“被忽略”退休 | 弱模型本来就会做，自然不需要照着做。现有的 `IGNORED_STREAK_LIMIT = 5`（`lifecycle.ts:73`）会误杀好条目，手册条目不走这条规则 |
| 对照组 | 按会话分组：10% 的会话整场不递，只按来源汇总效果。单条条目样本太少，提升量永远算不出来。演示时关掉对照组 |

## 7. 分期

| 期 | 内容 |
|---|---|
| 一期（为视频） | 复盘工具和校验；抽挂钩（Python、蓝图/控件/输入参数、`update_plan`）；递送（挂在结果后面，加上 `search_tools` 加载时）；思路技能的提示；账本只计数。**这一期复盘写进来的卡片一律是“试用”**，只有经过引擎核实的事实类条目才标“已验证”。老师那次成功只能证明老师做对了，证明不了卡片对学生有用 |
| 二期 | 扩展探针、按会话对照、新的记功规则、设置页按来源筛选、手册随技能共享（见第 7.1 节） |
| 三期 | 弱模型拿着手册先试跑，补上真实的负例 |

### 7.1 手册随技能共享

不另做“手册包”。复盘留下的手册和思路，打包成一份普通技能：正文放思路，卡片放进 `references/` 下的一个文件。然后走已经上线的共享技能，上传、安装都用现有流程。这样换一台机器也能用。

**安全**：装进来的卡片会被递给模型，所以它们和技能正文一样，都是一个注入口。从共享装进来的卡片，默认以“试用”状态进入，不参与执行前拦截，必须在本机被引擎核实过才能转成“已验证”。

## 8. 评测

**题目**：5 个变体任务，比如僵尸潮 ÷ 门、滚雪球、太空蜂群光环，每组跑 3 次。

| 组 | DeepSeek 拿到的东西 |
|---|---|
| ① | 什么都不给 |
| ② | 只有思路 |
| ③ | 思路 + 递送 |
| ④ | 思路 + 把全部条目直接放进提示词 |

**指标**：人工评分表（能换道、门会改数量、人群能显示、能交战、数字能显示），Python 报错次数，调用次数，token。

如果 ④ 不比 ③ 差，就说明条目还少的时候，全量放进提示词更简单。递送要到条目多到几百条、跨好几个领域时才显出价值。

## 9. 风险

1. **“新手会错在哪”是老师猜的。** 所以正文只写正确做法，错法只当挂钩用；有没有用，由弱模型实际踩没踩坑来定。
2. **设计选择会被当成事实。** 比如“人群用 ISM”，在需要单体动画的变体里就是错的。这类条目必须写明适用条件，或者放进思路。
3. **递送条目要另起一套记功规则**，原来的生命周期不能直接套用。
4. **通用层存在 userData 里，换一台机器就带不走。** 二期通过共享技能解决（第 7.1 节）；一期演示时始终用同一台机器。
